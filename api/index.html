What this tool will not do

  • Does not search live paper databases: It uses parametric knowledge and heuristic structure; it does not query live arXiv or IEEE APIs to verify current citation counts.

How ScholarScope Evaluates Topics

A deterministic 6-stage pipeline combining heuristic boundaries, prompt chaining, programmatic rubric verification, and cloud persistence.

The 6-Stage Pipeline

0

Stage 0: Heuristic Input Guardrails

Validates character count (8 to 300), alphabet ratio, and regex checks for prompt injection keywords before making any LLM calls.

1

Stage 1: Topic Understanding

Analyzes research domain, core question, and determines if the proposal can be framed as an academic hypothesis without scoring pressure.

2

Stage 2: Feasibility Scoring

Evaluates the four rubric pillars (Scope, Resources, Sources, Measurable Outcomes) on a 1 to 5 scale using calibrated few-shot anchors.

3

Stage 3: Programmatic Rubric Validation

Python-based validator verifies JSON structure, confirms individual scores match the total, and audits justification citations without an LLM judge.

4

Stage 4: Feasibility Report Synthesis

Synthesizes an academic markdown report containing executive findings, resource constraints, and next steps.

5

Stage 5: Google Sheets Persistence

Transmits exactly 11 standard columns to a cloud Google Sheet via an authenticated Google Apps Script Web App webhook.

The 3-Stage Programmatic Validator & Retry Rule

1. Structure Check

Verifies JSON schema integrity: checks that all 4 criteria keys are present, scores are integers within [1, 5], and reasons have at least 15 characters.

2. Mathematical Consistency

Enforces that the reported total equals the exact sum of individual criterion scores, and that the verdict matches rubric thresholds (Feasible ≥16, Refine 11-15, Not Feasible ≤10).

3. Quality & Grounding

Verifies that justifications cite findings from the Stage 1 topic analysis rather than inventing external facts or generic placeholders.

Automated 1x Retry Rule

If the validator detects an arithmetic or schema discrepancy, it extracts the exact violation as a correction hint and re-invokes Stage 2 once. If the retry passes, the correction is logged to the sheet Notes column; if it fails again, the pipeline stops and flags validation failure.

Prompt Engineering Evolution

Comparative analysis across the three scoring prompt versions using real saved benchmark results.

Baseline

Version 1: Zero-Shot

Instructs the model to score the four criteria 1 to 5 without concrete rubric descriptions or anchor examples.

Technique: Zero-shot direct prompting
Behavior: Optimistic scoring, high variance across runs, arbitrary totals.
Failure Mode: Vague topics receive inflated scores due to lack of constraints.
Calibrated

Version 2: Few-Shot Rubric

Adds explicit behavioral anchor descriptions for scores 1, 3, and 5, with two worked few-shot demonstrations.

Technique: Few-shot + Rubric calibration
Behavior: Penalizes unrealistic topics properly, consistent score ranges.
Failure Mode: Occasional arithmetic total mismatches under long outputs.
Active Default

Version 3: Structured CoT

Enforces a "reasoning first, score second" schema, calibrates for undergraduate resource limits (1 laptop, 1 semester), and includes leak-free anchors.

Technique: Chain-of-Thought + Strict JSON Schema
Behavior: High justification rigor, 100% arithmetic adherence, zero anchor bias.
Precaution: Worked example switched to "Technology in education" to prevent leakage on T2.

Responsible AI & System Safety

Operational boundaries, safety guardrails, anti-hallucination policies, and data transparency principles.

1. System Limitations

ScholarScope relies on parametric LLM knowledge rather than querying live scholarly search engines (like Semantic Scholar or Google Scholar). It cannot confirm whether a specific dataset link is currently active or measure up-to-the-minute arXiv publication counts.

2. Zero Invented Sources Policy

The Stage 3 quality validator checks that score justifications do not invent external facts or contradict observations established in Stage 1 topic analysis. The system is instructed to acknowledge ambiguity rather than fabricate benchmark numbers.

3. Human-in-the-Loop Oversight

The tool is strictly an advisory aid designed to help students prepare for supervisor discussions. It does not replace faculty guidance, departmental ethics clearance, or formal project defense panels.

4. Transparent Cloud Storage

Every evaluation request, prompt version, numerical score, and validation log is appended directly to an auditable Google Sheet via an authenticated Apps Script Webhook. No data is stored in unmonitored hidden databases.
