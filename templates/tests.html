Prompt Architecture Evolution (V1 vs V2 vs V3)

Systematic improvements across iterations: why each change was made and how it resolved failure modes.

Engineering Dimension Version 1 (Baseline) Version 2 (Few-Shot Calibrated) Version 3 (Production Anchored)
Technique Zero-shot directive prompting with generic instructions. 1 few-shot calibrated example in prompt body. Domain-separated few-shot anchor with explicit negative constraints.
Anchor Topic None (model relied on internal bias). Topic was “Sentiment analysis of student feedback” (collided directly with test case T1). Topic changed to “IoT soil moisture sensor” (completely distinct domain, zero leakage).
Few-Shot Leakage None (no examples). High vulnerability: Model memorized exact scores for T1 rather than evaluating. Zero leakage: Works across NLP, computer vision, embedded systems, and civil topics.
Scoring Rubric Anchor Vague 1–5 range without explicit undergraduate boundary conditions. Anchor points defined for 1, 3, 5 across all 4 criteria. Strictly anchored: 4 weeks time horizon, 8GB laptop RAM, open-access papers only.
Anti-Hallucination Gate None (unstructured reasons permitted). Required reasoning strings for each criterion. Validator Gate 3 verifies that reasons cite exact phrases from the Stage 1 analysis text.
Output Format Loose JSON (frequent trailing markdown fences and markdown wrap). Strict JSON object schema enforced in prompt text. Pydantic-compliant raw JSON with deterministic 3-stage validation and single retry.
