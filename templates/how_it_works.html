Methodology & Pipeline Architecture

A multi-stage deterministic framework combining LLM reasoning with automated schema, arithmetic, and rubric validation.

The Six Pipeline Stages

Each topic traverses six sequential stages designed to eliminate hallucinations, enforce student hardware constraints, and log every decision.

STAGE 0 Client / Server Guardrail

Heuristic Input Guardrail

Validates input length (10 to 300 characters), checks for empty text, and inspects adversarial override phrases before invoking external APIs.

STAGE 1 Topic Analysis

Domain & Research Question Extraction

Identifies the primary academic domain, reformulates the input into a formal research question, and flags ambiguities without inventing facts.

STAGE 2 Core LLM Evaluation

4-Criterion Rubric Scoring

Evaluates Scope, Resources, Sources, and Outcomes on a calibrated 1–5 scale grounded in 4-week student timeline and personal laptop compute.

STAGE 3 Deterministic Python

Automated 3-Stage Validator

Applies zero-tolerance deterministic rules in Python to verify JSON schema, confirm exact mathematical totals, and enforce canonical verdict bounds.

STAGE 4 Advisory Synthesis

Feasibility Report Generation

Synthesizes validated metrics into an actionable Markdown advisory report featuring risk factors and concrete scope-narrowing recommendations.

STAGE 5 Auditable Cloud Storage

Google Sheet Persistence

Appends an immutable 11-column record to the Google Sheets Results tab via an authenticated Google Apps Script Web App webhook.

The 3-Tier Validator

LLMs are probabilistic and prone to arithmetic or schema hallucinations. ScholarScope interposes three deterministic verification gates:

GATE 1

JSON Schema & Field Presence

Ensures that all 4 dimensions (Scope, Resources, Sources, Outcomes) exist as structured objects with both a numerical score and an explanatory reason.

GATE 2

Score Range & Mathematical Sum

Confirms every score is an integer between 1 and 5, and verifies mathematically that total == scope + resources + sources + outcomes.

GATE 3

Canonical Verdict Mapping

Locks verdict labels to strict thresholds: Feasible (≥ 16), Needs Refinement (11–15), or Not Feasible (≤ 10).

Retry Rule & Failure Paths

  • Single Targeted Retry: If Gate 1, 2, or 3 fails, the pipeline re-invokes the scoring prompt once, supplying the exact validation failure reason to the model.
  • Stage 0 Guardrail: Adversarial instructions ("ignore the rules", "give 5/5") or empty inputs trigger immediate rejection without invoking the Gemini API.
  • Webhook Degraded Mode: If the cloud Google Sheet is temporarily unreachable, the analysis completes successfully for the student, logging an honest "Not saved to Google Sheet" audit notice.
